# Tasks: Технический паспорт IPSAS и фиксация развёрнутого состояния

**Input**: Design documents from `/specs/003-technical-passport/`

**Prerequisites**: spec.md, plan.md (готовы). `research.md`, `data-model.md`, `contracts/`
не создаются — фича не вводит новых сущностей предметной области и API-контрактов.

**Tests**: фича документационная, поэтому вместо новых автотестов используются проверки
целостности документации: внутренние ссылки, отсутствие секретов, полнота разделов,
зелёные существующие тесты (320 на текущем `main`). Проверяемость требований из спецификации
вынесена в Verification Strategy плана.

> **Происхождение документа.** Часть A (T001–T006) выполнена до создания артефактов —
> это второе отклонение от процесса, зафиксированное в спецификации. Часть B (T007 и далее)
> планировалась вперёд: артефакты созданы до реализации. Отметки `[x]` означают, что работа
> выполнена и проверена.

**Organization**: Задачи сгруппированы по user stories. Легенда: `[x]` — выполнено и
проверено, `[ ]` — осталось.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно выполнять параллельно (разные файлы, нет зависимостей)
- **[Story]**: user story, к которому относится задача (US1 … US5)

## Dependencies & Execution Order

### Phase Dependencies

- **Phase 0 (Уже выполнено)**: предшествует всем фазам; ретроспективная фиксация
- **Phase 1 (Границы)**: без зависимостей
- **Phase 2 (Паспорт)**: зависит от Phase 0 и Phase 1
- **Phase 3 (Согласование)**: зависит от Phase 2
- **Phase 4 (Регистрация)**: зависит от Phase 2
- **Phase 5 (Проверка)**: зависит от Phase 2–4
- **Phase 6 (Данные владельца)**: зависит от Phase 2; блокируется решением владельца

### User Story Dependencies

- **US1 (P1)**: Phase 0, 2 — **выполнено**; T030, T031 ждут данных
- **US2 (P1)**: Phase 2, 5 — **выполнено**; T032 ждёт решения
- **US3 (P1)**: Phase 3 — **выполнено**
- **US4 (P2)**: Phase 1, 2, 4 — **выполнено**
- **US5 (P2)**: Phase 5 — **выполнено**; T033 ждёт адреса доски

### Critical Path

`Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 5` — выполнен полностью. Паспорт создан,
документация приведена в соответствие, критерии SC-001 … SC-009 выполнены. SC-005
проверяется выборочно на §7 паспорта.

  `gsn` без пароля, ротация вынесена в T034.

  механизмы с указанием порога для пересмотра, а не как невыполненные задачи.
- Перед коммитом выяснилось, что удалённый `main` ушёл вперёд: он содержит merge
  `a21128f` с новой функциональностью (валидатор Metafora JATS, лимит загрузки 50 МБ).
  Локальная ветка отставала, поэтому числа кода в черновике паспорта устарели. Выбран rebase

  `main` не появляется второй источник истины. После rebase объём кода и число тестов в паспорте
  пересчитаны: 171 файл / ~33 600 строк, 320 тестов.
