# Implementation Plan: Лимит загрузки файлов 50 МБ

**Branch**: `004-upload-limit-50mb` | **Date**: 2026-10-05 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-upload-limit-50mb/spec.md`

## Summary

Привести лимит загрузки к 50 МБ сквозным образом. Код приложения уже имеет дефолт 50 МБ, но
production-шаблон окружения задаёт 10 МБ, а nginx — 12 МБ, и именно эти два файла определяют
поведение развёрнутого экземпляра. Изменение — конфигурационное, плюс небольшая правка дефолта
в `settings.py` (запас под multipart) и автотест согласованности.

Технический подход: значения лимитов живут в трёх местах, и соглашение между ними выражается
явно и проверяется машинно. `MAX_FILE_SIZE` = 50 МБ; `MAX_CONTENT_LENGTH` = 55 МБ (запас под
multipart); `client_max_body_size 55m` в nginx. Автотест читает конфиги из репозитория и
проверяет инвариант «nginx ≥ тело > файл». Бизнес-логика сервисов не затрагивается: меняются
только конфигурация, дефолт настроек, документация и тест.

## Technical Context

**Language/Version**: Python 3.11 (правка `ipsas/config/settings.py`), nginx (правка конфига),
Markdown (документация).

**Primary Dependencies**: без изменений. Затрагиваемые модули: `ipsas/config/settings.py`
(дефолты), чтение файлов в тесте через `pathlib`.

**Storage**: не применимо.

**Testing**: `pytest`. Добавляется `tests/test_upload_limits.py` (чтение файлов репозитория,
без сети). Baseline — 320 тестов.

**Target Platform**: Linux-сервер с Docker Compose за nginx; dev-машины с `.env.example`.

**Project Type**: веб-приложение (Flask), фича затрагивает конфигурацию и документацию.

**Performance Goals**: не применимо.

**Constraints**: имена переменных `MAX_FILE_SIZE` / `MAX_CONTENT_LENGTH` — публичный
интерфейс; единицы nginx `m` — мебибайты; секретов в артефактах нет.

**Scale/Scope**: 1 правка кода (дефолт `settings.py`), 4 конфигурационных файла, 4 документа,
1 новый тест, 3 артефакта спецификации.

## Implementation Phases

### Phase 0: Источник истины

Определить единственное место, где вычисляется запас под multipart, и выразить через него
дефолт `settings.py`. Значения в шаблонах задаются явно в байтах, но должны совпадать с
дефолтом и проходить тест. Без выдуманного реестра: значений мало, они статичны.

### Phase 1: Дефолт кода

В `ipsas/config/settings.py` дефолт `MAX_CONTENT_LENGTH` становится `MAX_FILE_SIZE` плюс запас.
Правка точечная, без нового модуля.

### Phase 2: Конфигурация

Согласовать `.env.example`, `deploy/ipsas.env.production.example` и
`deploy/nginx.example.conf`. Значение nginx — в мебибайтах, но ровно в байты `MAX_CONTENT_LENGTH`
численно.

### Phase 3: Автотест

`tests/test_upload_limits.py`: парсит конфиги, проверяет инвариант, читает дефолты настроек,
падает с явным сообщением о файле и значении.

### Phase 4: Документация

`DEPLOYMENT.md`, `RAILWAY_DEPLOY.md`, `deploy/SERVER_DEPLOY.md` — согласованные значения и
диагностика.

### Phase 5: Проверка

Механическая сверка всех утверждений спецификации, `pytest`, ссылки; затем применение на
сервере по инструкции (вне репозитория).

## Verification Strategy

| Что | Как проверяется | Результат |
|-----|-----------------|-----------|
| Тест согласованности существует и проходит | `pytest tests/test_upload_limits.py` | SC-001 |
| Значения 50 МБ в обоих шаблонах | тест читает `.env.example` и production-шаблон | SC-002 |
| nginx ≥ тела запроса | тест парсит `client_max_body_size` и сравнивает в байтах | SC-003 |
| Дефолт тела > дефолт файла | тест читает дефолты `settings.py` | SC-004 |
| Нет значений 10/12 МБ | поиск по конфигам и документации | SC-005 |
| Ссылки целы | проверка внутренних ссылок Markdown | SC-006 |
| Файл 50 МБ проходит на экземпляре | ручная загрузка на сервере после применения | SC-007 |
| Регрессий нет | `pytest` полностью | ≥ 320 |

## Risks & Trade-offs

- **Больший лимит тела увеличивает поверхность приёма данных.** Компромисс принят: файлы
  выпусков уже доходят до десятков мегабайт, а обработка по-прежнему проходит ZIP/XML-защиту.
  Защита от «бездонного» приёма сохраняется: предел тела конечен и равен 55 МБ.
- **Запас 5 МБ может оказаться мал для форм с несколькими файлами.** Для текущих сервисов
  загружается один файл за запрос; при появлении многолетних форм значение пересматривается.
- **Тест читает текст конфигов.** Формат `m` у nginx и `KEY=VALUE` у env разбираются вручную;
  тест покрывает именно эти форматы и упадёт при их изменении, что приемлемо — это и есть
  сигнал пересмотреть проверку.
- **Дефолт кода меняется.** Это единственная правка рантайма в фиче. Риск низкий: значение
  не влияет на логику, только на порог отказа, и покрыто тестом.

## Future Work

- Включить проверку `client_max_body_size` против фактической конфигурации nginx на
  развёрнутом экземпляре (сейчас тест проверяет только пример из репозитория).
- Внести связь «nginx ≥ тело > файл» в `deploy/nginx.example.conf` как генерируемую проверку,
  если шаблонов nginx станет больше одного.
- Оценить, не нужен ли отдельный лимит для сервисов с многолетними формами.

## Notes

- Причина дефекта — рассинхрон слоёв; фича лечит не только значение, но и отсутствие проверки.
- Исторические артефакты `specs/001` и `specs/003` упоминают лимит 10 МБ как факт своего
  времени; они не правятся, поскольку фиксируют прошлое состояние.
- Применение на сервере (перезагрузка nginx, пересоздание контейнера) выполняется оператором и
  в репозитории не автоматизируется.
