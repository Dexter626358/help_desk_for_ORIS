## 2. Проблемы сервиса проверки (баги / ложные срабатывания)

### 2.1. `step2.focus` — не читается поле `focusScopeDesc` (критично)

- В чек-листе ищутся `focusAndScope` / custom about.
- В экспортах RAS предметная область лежит в **`focusScopeDesc`** (заполнено у **135/141** журналов).
- Из-за этого проверка ставит **fail почти всем** (140/141, 99.3%), хотя текст часто уже есть.
- Если добавить `focusScopeDesc` в ключи проверки: **ok 135 / fail 6**.

**Вывод:** массовое ложное замечание. Нужно расширить `setting_keys` для `step2.focus`.

### 2.2. `modules.recognition` — плагины есть, но выключены (не баг, но шум)

- В экспорте почти у всех есть `referralplugin` / `ResolverPlugin`, но `enabled=False` (≈139–140).
- Включены реально только у единиц.
- Проверка корректно считает fail, но формулировка `actual: ResolverPlugin` может выглядеть как будто плагин уже «есть» — лучше явно писать «найден, но выключен».

### 2.3. Высокая доля ручных проверок `modules.webfeed` (98.6%)

- 139/141 уходят в ручную проверку.
- Для пакетного прогона RAS это почти бесполезно: отчёт не закрывает пункт автоматически.
- Имеет смысл уточнить критерии автооценки новостной ленты по `.data` или понизить severity / вынести в рекомендации.

### 2.4. `step4.access` — массовый `partial` / warn (73.8%)

- Часто: «Проверьте роли регистрации (автор/читатель/рецензент)».
- Не падение, но сильно раздувает блок «заполнено частично» и требует ручного внимания проверяющего.

### 2.5. Стабильность сервиса

- Падений, пустых `fields`, битых писем (`letter_payload`) на массиве **не обнаружено**.
- У всех пунктов письма в выборке есть `fix_path` (инструкции подставляются).

### Разбор частых пунктов

1. **`step3.copyright` (99.3%)**  
   Текст `copyrightNotice` часто есть (≈127), но почти всегда нет `licenseURL` / лицензии. Типичный дефицит: «указать сведения о лицензии». Это реальное содержимое, не ложный fail.

2. **`step3.checklist` (97.2%)**  
   `submissionChecklist` отсутствует у ≈123 журналов. Реальный пробел настройки.

3. **`step1.indexing_kw` (84.4%)**  
   Пустые `searchKeywords` RU/EN. Реальный пробел.

4. **`step5.dates` (83.7%)**  
   Не включены флаги вроде `displayIssuePublishDate` / `displaySubmissionPublishDate`. Реальный пробел шага 5.9.

5. **`pages.section_articles` (45.4%)**  
   Чаще всего: нет ограничения «только редакторы» и/или раздел не скрыт в «О журнале». Названия RU/EN обычно есть.

6. **Частичные (partial)**  
   - `step5.cover` / `step5.thumbnail` — ~67–68%  
   - `step3.guidelines` — ~60% (часто только один язык)  
   - `step2.review` — ~30%

## 4. Рекомендации по доработке сервиса

1. **Срочно:** учитывать `focusScopeDesc` (и при необходимости синонимы) в `step2.focus`, иначе RAS-выгрузки массово ложно красные.  
2. Уточнить отображение для recognition-плагинов: «есть в экспорте, выключен».  
3. Пересмотреть авто/ручную логику `modules.webfeed` и `step4.access` для пакетных проверок.  
4. Опционально: batch-режим CLI/отчёт по каталогу `.data` (как этот прогон) — полезен для RAS.

## 5. Примеры журналов

### Наименьшая готовность (фрагмент)

См. `worst_journals` в `temp/ras_settings_batch_summary.json` (до 30 позиций). Типично 8–10 fail при ~75% mandatory.

### Наибольшая готовность (фрагмент)

Лучшие около 90–95% mandatory, но всё равно имеют 3–5 fail (часто copyright / recognition / checklist / focus до фикса ключа).
