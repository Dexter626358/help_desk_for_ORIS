# Обнаруженная схема данных OJS `.data` (RAS)

**Выборка для разведки:** 141 файл в `ras_settings/`, детальный разбор 8 стратифицированных журналов.  
**Формат файла:** JSON; верхний ключ — числовой `journal_id`, внутри объект экспорта.

## 1. Корневая структура

```text
{
  "<journal_id>": {
    "journal": { "path", "enabled", "primary_locale", ... },
    "settings": { "<settingName>": <scalar|localized|list|bool>, ... },
    "plugins":  { "<PluginName>": { enabled, settings, ... }, ... },
    "sections": [ { title, abbrev, hideAbout, editorRestriction, ... }, ... ],
    "staticPages": [ ... ],
    "files": { ... }   // технические вложения; на оценку готовности не влияют
  }
}
```

Парсер сервиса (`parse_journal_data`) разворачивает это в `JournalDataExport`.

## 2. Разделы и назначение

| Раздел | Назначение | Влияет на оценку |
|---|---|---|
| `journal` | path, primary_locale, enabled | частично (идентификация) |
| `settings` | все поля 5 шагов настройки + языки | **да** |
| `plugins` | модули/метрики/pubIds | **да** |
| `sections` | разделы журнала | **да** |
| `staticPages` | статические страницы | ограниченно |
| `files` | бинарные/служебные файлы | **нет** (техническое) |

## 3. Локали

- Основные ключи: `ru_RU`, `en_US` (в выборке доминируют).
- Текстовые поля часто вида `{"ru_RU": "...", "en_US": "..."}`.
- Пустое значение: ключ отсутствует, `null`, `""`, HTML без текста, пробелы.

Очистка текста для оценки: снятие тегов HTML и placeholder'ов `##...##`, нормализация пробелов.

## 4. Обязательные / рекомендованные (по чек-листу БАЗА сервиса)

Источник правил: `DEFAULT_SETUP_CHECKLIST` + уточнения независимого аудита.

**Обязательные (severity=required / critical в аудите):** языки RU/EN, название, ISSN, издатель, предметная область, рецензирование, правила авторов, copyright, ключевые модули, раздел «Статьи» и др. (см. `validation_rules.json`).

**Рекомендованные:** ACRON, «лишние модули», часть метрик по условию.

**Info:** спонсоры/финансирование — пусто допустимо.

## 5. Логические настройки

Примеры: `hideAbout`, `editorRestriction`, `displayIssuePublishDate`, `boardEnabled`, `enabled` у плагинов.  
Истина: `true` / `1` / `"1"` / `"true"`.

## 6. Поля, требующие уточнения правила (`requires_rule_clarification`)

| Поле / тема | Почему |
|---|---|
| `modules.doi` при выключенном плагине | Чек-лист: «если журнал присваивает DOI»; по `.data` намерение не всегда доказуемо |
| `metrics.plumx` / Scopus | Признак Scopus в экспорте ненадёжен |
| `modules.fundref` «обновить базу организаций» | В JSON нет подтверждения обновления |
| `modules.webfeed` страницы отображения | Плагин enabled есть; флаги страниц часто не видны |
| `publishingMode` / library mode | Нужна явная интерпретация допустимых значений |
| Формат идентификации выпусков | Допустимые комбинации полей не зафиксированы однозначно |
| `modules.extra_off` whitelist | Список «лишних» модулей эвристический |

## 7. Сопоставление с чек-листом сервиса

| Чек-лист | JSON-пути |
|---|---|
| Языки | `settings.supportedLocales*Form*` |
| Редакция | `settings.boardCustomText` |
| Разделы | `sections[]` |
| DOI/EDN/метрики | `plugins.*` |
| Шаг 1–5 | `settings.title`, `abbreviation`, `focusScopeDesc`, `reviewPolicy`, … |
| Предметная область | `focusAndScope` **или** `focusScopeDesc` (в RAS почти всегда `focusScopeDesc`) |

## 8. Предварительная стратификация заполненности (эвристика)

По числу непустых слотов ключевых текстовых полей (0–24 шкала разведки):

- низкая: ~11–15 (пример `0869-7698.data`);
- средняя: ~16–18;
- высокая: ~19–21 (пример `0235-0106.data`).

Абсолютно «пустых» журналов в RAS нет: базовые title/ISSN/плагины обычно заполнены.
